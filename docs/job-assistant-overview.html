§01 What it is

Job Assistant replaces the tangle of job boards, spreadsheets, a resume editor, scattered AI chats, and email alerts with a single, multi-tenant workspace.

Opportunities are discovered from many sources, scored against the user's profile, turned into tailored application materials and a real resume document, and tracked through an application pipeline — all driven by a built-in AI assistant. It runs as a personal tool or a multi-seat product with role-based access, and it's provider-agnostic on AI: plug in OpenAI, Azure OpenAI, Claude, Gemini, Hugging Face, or Ollama — or run on a no-key local fallback that never breaks.

§02 The unique idea

Closes the whole loop — and learns.

Most tools own one slice: a board, a resume writer, or a tracker. Job Assistant connects every slice, anchors it to the user's real profile, and gets better with use.

1

Profile-grounded, not generic

Scoring, tailoring, and resume generation are anchored to the user's structured profile and CV — with explicit guardrails telling the AI not to invent employers, dates, degrees, or metrics. Truthful by construction.

2

Many profiles → per-job targeting

Keep several resumes ("Backend roles", "Platform roles") and choose which one scores and tailors each individual job. One identity, many targeted applications.

3

A learning loop

Marking a scored job relevant or not feeds back into how future roles are scored for that user. Recommendation quality climbs with use.

4

Country-aware resume building

Resumes render as real .docx files in the conventions of a chosen region — US, UK, Europass, Canada, Australia, International.

5

Provider-agnostic AI with a floor

Any major LLM plugs in. If none is set or the daily budget is hit, the app degrades to local heuristics instead of failing.

6

Built for teams, too

The same engine runs solo or as a workspace-scoped product with RBAC, sharing, audit, and compliance — for coaches, bootcamps, or recruiting teams.

§07 AI routing & fallback

One path, always answers.

Every AI feature — scoring, extraction, tailoring, resume building, interview prep, chat — resolves through the same route, so behaviour is consistent and a valid result is guaranteed.

1
Use the active, prioritized provider from provider_configs (workspace-scoped).
2
Otherwise use the per-user integration_settings AI provider.
3
Otherwise fall back to local heuristics — no key required, never fails.

A daily generation budget is enforced; every call is logged with provider, model, tokens, latency, status, and estimated cost.

§09 How to use it

01

Sign up

Register and sign in — a personal workspace is created automatically.

02

Build your profile

In Settings → Profile, fill it in or Upload resume (PDF/DOCX/TXT) to auto-extract. Add named profiles for different target roles and set a default.

03

Connect AI

On the AI Provider page, pick your provider, paste the key, set model/endpoint, and save. Optional — the app still works on local heuristics.

04

Configure agent

Customize the assistant's persona under Settings → Agent Persona. Review or add agent memories under Settings → Agent Memory.

05

Find jobs

Use Find Jobs (from profile or public feeds), connect Gmail, or Add Job by pasting a URL or description.

06

Score & triage

Open a job, pick which profile to score against, run the score, and use 👍/👎 to teach it. Filter the list by status, type, or search.

07

Apply, tailored

Tailor resume, Build resume (DOCX) in your country's format, Generate materials, and Generate interview prep. Record practice answers if you like.

08

Track

Set status, add notes, and let automatic follow-up reminders keep stale applications on your radar.

09

Ask the assistant

At /agent: "find me remote backend roles," "tailor my resume for this job," "prep me for this interview." The agent remembers facts about you across sessions.

10

Monitor usage

Settings → Usage for daily budget, cost breakdown by task type, 30-day history, and rate-limit status.

11

Invite a team

Under Team, add members, assign roles, and share resources within a workspace.

§11 Notes & current limits

Datastore: MongoDB is the sole datastore (no SQLite in the stack).

LinkedIn discovery currently runs through RapidAPI / Apify; the native SDK module is a placeholder.

Azure reasoning/codex deployments (gpt-5.x, *-codex, o-series) require the Responses API — auto-detected by deployment name. AI quality tracks the configured provider; with none, features fall back to local heuristics.
